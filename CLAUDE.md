# ParentDesk (부모 행정 비서)

School notices (photo, PDF, pasted text, shared message, Gmail) → events, deadlines, payments, consent forms and to-dos per child, with a calendar feed. Live: https://parentdesk-app.vercel.app (Vercel project `parentdesk-app`, auto-deploys from `main`). Public repo: do not commit anything private.

## Secrets (never print, never commit)
- `ANTHROPIC_API_KEY` is a Windows **user** env var. Start the dev server with it from PowerShell: `$env:ANTHROPIC_API_KEY = [Environment]::GetEnvironmentVariable('ANTHROPIC_API_KEY','User'); npm run dev -- -p 3002`. Never echo it, never write it to a file, never pass it on a command line.
- `.env.local`, `.google-oauth.local`, `.admin.local` hold the local copies of Vercel env values; `*.local`, `.env*` (except `.env.example`) and `data/` are gitignored. Vercel is the source of truth (`npx vercel env ls`, `printf '%s' value | npx vercel env add NAME production --yes`).
- Google OAuth client lives in Google Cloud project `parentdesk-513816` (Testing mode: 7-day refresh tokens, unverified-app warning).
- Never run `npm run eval` or extraction scripts against production; use the local server.

## Stack and layout
Next.js 16 App Router + Turbopack, React 19, Tailwind 4, TypeScript, zod 4, `@anthropic-ai/sdk` (structured output via `betaZodOutputFormat`), `@vercel/blob` (one private JSON per family under `parentdesk/families/`, ops docs under `parentdesk/ops/`), vitest.
- `src/app/[locale]/…` pages (10 UI locales: en bare path, ko es ja zh fr de pt it vi prefixed; routing in `src/proxy.ts`; `/` is the landing page for visitors and the home dashboard (`DashboardView`, numbers from `lib/dashboard.ts`) for a family, `/week` the day-by-day list (`HomeView`); `/teach` is the teacher desk, `/join` handles both `?i=` partner invites and `?r=` room links), `src/app/admin` (operator console in Korean for the operator, outside locale routing: tabs for overview, families, teachers and rooms, schools, system; `/api/admin/list` for the tables, `/api/admin/action` for deletes, unlisting and clean-up, every action logged as an `adminlog/<id>` document; a family can carry the operator's note and a pause switch (`rec.admin`, 403 `blocked` on every model-spending route); one announcement for teachers and/or families (`ops/announcement`, `/api/announcement`, `Announcement` banner); optional second sign-in step with `ADMIN_TOTP_SECRET` (`lib/totp.ts`, `scripts/admin-2fa.mjs`), ten sign-in attempts an hour per address), `src/app/api/…` route handlers (`api/teacher/*` teacher side, `api/rooms/*` parent side of class rooms).
- `src/lib/`: `extract.ts` (model prompt + country packs from `knowledge/countries/*.md`), `schema.ts` (zod shapes, 21 result languages), `store.ts` + `types.ts` (family document, keys, invites, views), `rooms.ts` (teachers, class rooms, posts, fan-out delivery; documents `teachers/<id>` and `rooms/<id>`), `plan.ts` (Free/Family gating; everything is Family while Stripe keys are unset), `stripe.ts`, `digest.ts`, `gmail.ts`, `assist.ts` (ask, reply, inbox classifier, post translation), `dedupe.ts`, `admin.ts`, `ops.ts`, `i18n/*.ts` (dictionaries; `en.ts` is the source of truth and the parity test fails when a key is missing anywhere).
- Design rules to keep: no accounts (family key `pd_<id>_<secret>` and teacher key `pdt_<id>_<secret>` in HttpOnly cookies, hashes on the server, member keys from invite links), minimal child data (first name + colour only), uploads never stored, results shown with `dir="auto"`. Teachers never see family ids or names, only counts; a room post costs one extraction plus one translation per result language. A room may be listed (school · grade · class) in the directory parents search on `/join` (one `directory/<roomId>` document per listed room, `syncDirectory`/`touchDirectory`/`searchDirectory`, `/api/rooms/search` behind its own per-IP lookup limiter); finding is not joining: a listed room is joined with the six-character class code (`joinCodeOf`, derived from the join secret, rotates with the link) or the link/QR, unlisted rooms stay link-only. v0.11.1: a teacher's school has a place (`region`, `city`; suggestion lists in `lib/regions.ts`), schools converge on one `schools/<id>` entry (`schoolIdOf` = hash of country+place+name, `rememberSchool`, `/api/schools/search` with listed-room counts so a second teacher picks the same entry), directory entries carry place, `schoolId` and `lastPostAt`; the parent search matches place words, flags same-name schools, shows the last notice; the teacher desk warns when another teacher already lists the same school/grade/class and names a room after its grade and class when left blank.
- Models: extraction `EXTRACT_MODEL` (claude-opus-5-5), assistant `ASSIST_MODEL` (claude-sonnet-5-5: ask, reply drafts, item explanations `/api/items/[id]/explain`, room post translation), inbox classifier `CLASSIFY_MODEL` (claude-haiku-5-5). Every model path has a mock when no key is set. Home brief, packing list and the two-children clash warning are deterministic (`lib/dashboard.ts`), no model.

## Commands
```
npm run dev -- -p 3002        # local, with the API key in the environment (see Secrets)
npm test                      # vitest (about 100 tests; i18n parity, store, rooms, qr, dashboard, plan, stripe, digest, admin, gmail, dedupe, dates, ics)
npm run lint && npm run typecheck && npm run build
node scripts/errorcheck.mjs --url http://localhost:3002   # about 200 API error-path checks, no model calls (restart the dev server first if a previous run hit the 60/hour IP limiter)
node scripts/linkcheck.mjs  --url http://localhost:3002   # every page in every locale, internal links, API status codes
```
Run both scripts against production too after a deploy (default URL is production). Local families are JSON files under `data/families/`; edit them to simulate states (usage caps, billing) instead of spending model calls.

## Conventions
- New UI text goes into all 10 dictionaries in one patch (write a Node script with the Write tool; Korean on the command line garbles and commands over ~8 KB truncate on this machine).
- New optional features are env-gated and reported by `/api/health`; the UI hides what the server has not configured.
- API errors are `{ ok: false, error: "<code>" }` with codes mapped in `add.errors` of the dictionaries; 402 `plan_limit` is the plan gate, 429 the rate limiter.
- Keep `scripts/errorcheck.mjs` and `scripts/linkcheck.mjs` in step with new routes and pages, and add a vitest file per new lib module.
- Verify in the browser pane (viewport 375 px for phone checks) before declaring UI work done.
